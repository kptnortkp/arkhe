### Deviations from `backend.md`, with reasons

1. **Data model follows `db.md`, not `backend.md` §1.** Tickets have a uuid `id` plus a unique `number`; the thread is `board_ticket_events`; "seen" is `seen_event_id` + `seen_revision` (no `activity_rev`/`seen_rev`). The DBA tested it, including concurrency and restore, and D40 accepted it.
2. **Added `board_ticket_events.client_key`** (nullable, partial unique index, CHECK `client_key is null or kind = 'comment'`). `db.md` had no dedupe key for comments, but the PO recorded "forms carry a clientKey" (po-decisions §2). It is additive and inside the new migration.
3. **Moves bump `revision`** (D30), unlike `backend.md` §2.4. An editor opened before a move is refused with `TICKET_STALE`.
4. **Ticket create runs in `writeTx`, not one `db.batch`.** The replay check, the assignee check and the allocation must share one transaction. The counter upsert uses `max(last_number, max(number)) + 1`, so a counter behind the data heals instead of failing on the unique index.
5. **`markTicketSeen(number, eventId, revision) → { changed }`** (the rendered values from `getTicket().seen`), not `(number)` alone: an entry that lands between render and mount stays new.
6. **Field names.** Ticket form: `id` (create), `title`, `description`, `assigneeId`, `urgency`, `dueOn`, `status` (create only), `revision` (edit). Comment form: `clientKey`, `body`. Budget create/meta form: `id` (create), `name`, `start` (`YYYY-MM`), `note`. Plan editor: the 17 category codes as field names (`dues`, `travel`, …, not `amount.<category>`), plus `revision` and `reason`. Field errors use the same keys.
7. **Bound arguments:** `updateTicket.bind(null, number)`, `addComment.bind(null, number)`, `updateBudget.bind(null, id)`, `savePlan.bind(null, id)`. `moveTicket({ number, from, to })`, `deleteTicket(number)`, `deleteComment(id)`, `approveBudget(id, revision)`, `deleteBudget(id)`, `prefillPlan(id)` take plain arguments.
8. **`updateBudget` is last-write-wins and doesn't bump `revision`.** The revision guards plan amounts and approval ("approve what you saw"); renaming a draft or editing the note must not make an open plan editor stale. Approved: name/start changes → `APPROVED_LOCKED`, note saved without history (D34).
9. **The budget start-year bound is 2000 … Istanbul year + 10,** not + 2: AC 26 creates a January budget for `year(today) + 5`.
10. **Logged-out CSV request:** with no session cookie, the proxy answers 307 → `/giris` before the route runs (the same as `/finans/rapor/csv` today); with a stale cookie the route answers 401; korist@ gets 403. None returns a CSV body. D38's "401" therefore holds only for a stale cookie; the e2e should use `fetch(…, { redirect: "manual" })` and accept 307 for no cookie, or send a bogus cookie for 401.
11. **Unplanned lines get words too** (`₺300,00 fazla` / `₺50,00 aşıldı`), from the same `diffWords`. Their `pct` is null and the CSV `Gerçekleşme` cell is empty.
12. **Module names:** budget math is `src/lib/finance/budget.ts`, not `src/lib/budget/signals.ts` (it sits next to the finance queries and the D11 rule).
13. **Typed routes:** a stale `.next/types` from an earlier build hid the new routes from `tsc`. I regenerated it with `npx next typegen`; nothing in the repo changed.

### Deviations and choices

1. **No `beforeunload` guard in the plan editor** (UX §6.3, UI §5.3). A native leave-page prompt would interfere with AC 28, which reloads the editor on purpose (Playwright auto-dismisses dialogs, and a dismissed prompt cancels the navigation). The mitigation is the sticky save bar. P3 follow-up: a guard on the in-app links only.
2. **Report lines are cards at every width** (two columns from `lg`), not a table. AC 33 allows either, and one DOM avoids duplicate `data-testid`s (UI §5.5).
3. **Detail page**: a visible `Sil` button for the opener and the conductor instead of UX's `MoreHorizontal` overflow menu. Fewer controls; the same rule.
4. **The filter row wraps** at 375 px (`Herkes · Bana atananlar` on the first row, `Aciliyet` on the second) instead of scrolling sideways. Nothing is hidden off-screen, and there's no horizontal scroll.
5. **Column visibility keys on the URL slug** (`data-column="devam"`): Tailwind turns `_` in an arbitrary value into a space, so `in_progress` couldn't be matched.
